# 문서 관리 규칙

문서를 생성·수정·이동하거나 위키·README를 갱신할 때 필요한 절을 읽는다. 작업 순서는 [개발 작업 흐름](workflow.md)을 따른다.

## 역할과 기준 위치

| 문서 | 역할 |
| --- | --- |
| 루트 AGENTS.md | 모든 작업에 적용되는 최소 규칙과 조건별 탐색 안내 |
| .harness/ | 에이전트의 작업 수행·검증 절차와 규칙 |
| docs/ | 설계·계획·조사·실험 등의 미검증 입력 자료. 검증된 사실의 근거로 신뢰하지 않음 |
| openwiki/ | 검증을 거쳐 반영한 구조·동작·제약·중요한 결정 이유의 지식 베이스 |
| README.md | 허용된 지식 베이스에서 파생한 사람이 읽는 안내 |

세부 목차·분량·작성 도구는 강제하지 않는다. 기존 문서를 형식 통일만을 위해 다시 작성하지 않는다.

## 신뢰 경계와 링크

- AGENTS.md를 포함한 하네스 문서에서 docs의 개별 파일·하위 디렉토리로 연결하는 링크와 경로 안내를 두지 않는다. `docs/`라는 자료 계층의 역할 설명은 가능하지만 특정 문서로의 탐색 경로를 만들지 않는다.
- 프로젝트 지식으로 연결할 대상은 검증된 위키다. 아직 생성되지 않은 위키 링크를 만들거나, 위키 부재를 이유로 docs를 대신 안내하지 않는다.
- 현재 작업에서 지정된 docs 자료는 설계 리뷰·구현·위키 갱신을 위한 미검증 입력으로 읽을 수 있다. 문서가 존재하거나 리뷰되었다는 사실만으로 내용 전체를 검증된 지식으로 승격하지 않는다.
- 위키 반영 전 사용자 결정, 코드·테스트·실험 증거와 대조한다. 설계 결정의 확인과 실제 동작의 검증을 구분하고 미확인 내용은 사실로 반영하지 않는다. 위키에 저장하는 행위 자체가 검증은 아니다.

## 겹치는 정보와 갱신 경계

- 주제가 겹치는 것은 허용한다. 주된 목적이 행동 지시인지 프로젝트 설명인지 판단하여 배치하고, 상세 정보의 기준 위치는 하나만 유지한다. 다른 문서는 신뢰 경계를 지키는 범위에서 필요한 요약과 링크를 제공한다.
- 예를 들어 필수 검증 절차는 하네스에, 테스트 환경과 동작·한계에 대한 설명은 위키에 둔다. 짧은 문서를 구분만을 위해 억지로 분할하지 않는다.
- 위키는 프로젝트 맥락이며 에이전트의 작업 지시가 아니다. 위키 갱신 결과만으로 하네스 규칙을 자동 변경하지 않는다. 하네스 변경은 사용자와 합의한 작업 방식의 변경으로 명시한다.
- 위키의 설계 제약은 변경 시 확인해야 할 지식이다. 제약을 바꾸려면 의도한 설계 변경으로 명시하고 검증한다. 모든 설계 제약을 하네스에 복제하지 않는다.
- 사용자 결정, 확인한 코드·테스트·실행 결과 등 원자료로 담당 문서를 갱신한다. 설명과 구현이 다르면 원래 결정과 구현 근거를 확인하며, 근거 없는 내용은 미확정으로 남긴다.
- 설계 의도·가설·구현 상태·검증 결과를 구분한다. 문서만으로 현재 동작을 단정하지 않는다.
- **README를 AGENTS·하네스·근거 문서·위키의 작성 또는 갱신 근거로 역참조하지 않는다.**

## 위키 갱신

- 미검증 입력 자료는 `docs/` 아래에 보관한다. 갱신 요청에서 대상 문서를 하나씩 지정하고 OpenWiki의 기존 스킬·도구로 검토한다. 하네스에 입력 파일 링크를 상시 등록하지 않는다.
- 입력 문서 하나가 출력 페이지 하나를 의미하지 않는다. 관련 코드·테스트와 기존 위키를 확인하고 영향받는 페이지에만 반영한다.
- 책임, 관계, 제약, 중요한 선택 이유, 검증된 동작과 한계를 남긴다. 논의 전체와 작업 목록을 복제하지 않는다.
- 기존 기준 페이지에 통합하고 다른 페이지는 요약과 링크로 연결한다. 이미 반영된 정보라면 변경하지 않는다.
- 원본 설계·계획은 작업 기록으로 보존한다. 설계 변경과 실제 구현의 차이를 구분한다.
- 실제 위키 생성·갱신 완료 여부를 도구 결과로 확인한다. 수동 문서 이동을 OpenWiki 갱신 완료로 보고하지 않는다.

## README 갱신

- README의 지식 베이스는 **AGENTS.md와 관련 하네스·위키 문서 전체**다. AGENTS.md에 한정하지 않되, 현재 작성에 필요한 문서·섹션만 선택해서 읽는다.
- **docs/의 정보는 관련 하네스 또는 위키에 반영되기 전까지 README의 직접 근거로 사용하지 않는다.** 위키가 없는 경우에도 직접 근거 사용의 예외를 두지 않는다.
- AGENTS나 하네스에 docs 링크를 추가하지 않는다. 검증 없이 내용을 복사하는 것도 정보 반영으로 인정하지 않는다. 제품 지식은 위키에, 작업 절차는 하네스에 정리한다. README를 채우기 위해 제품 설계를 하네스에 복사하지 않는다.
- 허용된 근거가 없는 기존 README 내용은 근거 문서에 보존된 것을 확인한 뒤 README에서 제외한다.
- 허용된 지식 베이스에 반영된 내용만 바탕으로 사람이 읽기 쉬운 흐름과 표현을 사용한다. 내부 지침 전체를 복사하지 않는다.

## 문서 변경 검증

정보 누락, 기준 정보의 중복, 링크 유효성, 하네스의 docs 링크·경로 안내 부재, README 근거 범위, 계획·구현 상태 구분을 확인하고 `git diff --check`를 실행한다. 검증하지 않은 사실을 완료했다고 기록하지 않는다.
