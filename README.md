# LLM Serving Lab

**Kubernetes에서 LLM 추론 서버의 종료·교체 안정성을 재현하고 검증하는 실험 프로젝트입니다.**

> 현재 설계 단계입니다. 아래 구성은 구현 예정이며, 실행 가능한 Operator와 실험 도구는 아직 없습니다.

## 어떤 문제를 다루나요?

추론 서버를 축소하거나 새 버전으로 교체할 때, 진행 중인 스트리밍 응답은 끝까지 전달될까요?

이 프로젝트는 요청이 중단되는 조건을 반복해서 재현하고, 클라이언트 기록과 서버 종료 과정을 연결해 원인을 분석합니다. 설정이나 코드를 변경한 뒤 같은 실험으로 개선 효과와 종료 시간의 영향을 비교합니다.

첫 번째 목표는 **다른 사람도 스트리밍 중 종료·교체 실험을 재현하고, 요청 결과와 종료 타임라인을 확인할 수 있게 만드는 것**입니다.

## 어떻게 구성하나요?

| 구성 | 역할 |
| --- | --- |
| `ModelServing` | 추론 서버의 Deployment·Service와 배포 설정 관리 |
| `ExperimentRun` | 대상 서버를 참조해 부하·종료·교체 실험을 조율하고 결과 판정 |
| 공용 관측 인프라 | 지표·로그 수집과 실험 결과 저장 |

서빙과 실험은 수명주기가 다르므로 별도 CR로 관리합니다. 실험을 삭제해도 기존 추론 서버는 유지됩니다. 두 Reconciler는 처음에는 하나의 Operator에서 실행할 계획입니다.

```text
서버 준비 확인 → 스트리밍 부하 발생 → 처리 중 종료·교체 유발
                                              ↓
                         요청 결과와 종료 타임라인 수집·분석
```

## 무엇을 확인하나요?

- **결과:** 요청 중단율, 완료율, 종료 소요 시간, 응답 지연
- **원인:** 클라이언트 요청 기록, 서버 로그, Kubernetes 상태 변화
- **재현 조건:** 이미지 버전, 모델, GPU 종류, 서버 설정, 부하 조건

실험이 정상적으로 끝났더라도 요청 중단이 발생하면 검증 기준에는 실패할 수 있습니다. 원본 기록은 외부 저장소에 보관하고 CR에는 상태와 결과 요약·위치를 남길 계획입니다.

## GPU 없이도 개발할 수 있나요?

로컬에서는 가짜 추론 서버(faker)로 로딩 지연, 긴 스트리밍, 종료 동작을 재현합니다. 실제 엔진 검증이 필요한 시점에만 GPU VM을 사용합니다.

| 환경 | 용도 |
| --- | --- |
| 로컬 Kubernetes + faker | Controller와 실험·판정 도구 개발 |
| GPU VM의 독립 Kubernetes | 실제 추론 엔진의 동작 검증 |

두 환경에 같은 Operator와 환경별 설정을 적용할 계획입니다. GPU VM은 로컬 클러스터에 조인하지 않으며, 결과를 외부에 저장한 뒤 정리합니다. 환경 재구축은 자동화할 예정입니다.

faker에서 확인한 결과와 실제 GPU 검증 결과는 구분합니다.

## 어디에 활용하나요?

- 오픈소스 문제의 최소 재현 사례와 수정 전후 증거 제공
- 추론 엔진 버전 변경 시 회귀 검증
- 종료·배포 설정을 선택하기 위한 비교 자료
- 문제 정의부터 디버깅과 검증까지 보여주는 기술 포트폴리오

기여 대상과 수정 내용은 실제 문제가 확인된 뒤 결정합니다.
