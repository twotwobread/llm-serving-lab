# LLM Serving Lab

Kubernetes에서 LLM 추론 서버의 종료·교체 안정성을 재현하고 검증하기 위한 실험 프로젝트입니다.

현재는 설계 단계이며, 아래 구성은 구현 예정입니다.

## 첫 번째 검증 문제

추론 서버를 축소하거나 교체할 때 진행 중인 스트리밍 요청이 어떤 조건에서 중단되는지 재현하고, 원인을 분석한 뒤 개선 효과를 검증합니다.

- 측정: 요청 중단율, 완료율, 종료 소요 시간, 응답 지연
- 증거: 클라이언트 요청 기록, 서버 로그, Kubernetes 리소스 상태 변화
- 활용: 오픈소스 문제 재현·기여, 버전 변경 회귀 검증, 운영 설정 비교

## 구성 방향

- `ModelServing`: 추론 서버의 Deployment·Service와 배포 설정 관리
- `ExperimentRun`: 대상 서빙 리소스 참조, 부하 발생, 종료·교체 시나리오 조율, 결과 판정
- 공용 관측 인프라: 지표·로그 수집과 실험 결과 저장

두 CRD의 Reconciler는 우선 하나의 Operator에서 실행합니다. 실험은 기존 서버를 참조하며, 서버 리소스의 소유권을 갖지 않습니다. 실험 완료와 검증 통과를 구분하고, 원본 측정 데이터는 CR status 외부에 저장합니다.

## 개발 및 검증 환경

1. 로컬 Kubernetes와 가짜 추론 서버로 로딩 지연, 스트리밍, 종료 동작을 재현합니다.
2. 실제 GPU 검증 시에만 GPU VM에 독립된 Kubernetes 클러스터를 구성합니다.
3. 동일한 Operator와 환경별 설정으로 실험하고 결과를 외부에 저장합니다.
4. GPU VM을 삭제하며, 환경 재구축은 자동화합니다.

로컬 클러스터에 원격 GPU 노드를 조인하는 구성은 초기 범위에 포함하지 않습니다. 가짜 서버의 결과와 실제 추론 엔진 검증 결과를 구분합니다.

## 첫 완성 기준

다른 사람이 제공된 구성과 절차로 스트리밍 요청 중 서버 종료·교체 실험을 재현하고, 요청 결과와 종료 타임라인을 확인할 수 있어야 합니다.

실험 결과에는 이미지 버전, 모델, GPU 종류, 서버 설정, 부하 조건을 기록합니다. 오픈소스 기여 대상과 수정 내용은 실제 문제를 확인한 뒤 결정합니다.
